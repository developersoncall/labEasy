Medis Project Update Log

Detailed changes logged on August 09, 2026, addressing global app renaming, database sync anomalies, and admin experience improvements.

🔄

Health Package Data Synchronization

Fixed parameters and test checklist reset behavior on DB updates

Fixed

Resolved an issue where updating packages via the Medis Admin dashboard was writing empty checklists (`[]`) and losing package metadata. `pkgFromRow` and `pkgToRow` mappings did not previously handle the integration fields correctly, causing database sync anomalies.

Core Improvements Made:
  • Database Field Mappings: Restored reading and writing of database parameters (`category`, `ideal_for`, `fasting_required`, `report_hours`, `is_popular`, `home_collection_available`, and `included_tests`).
  • Interactive Test Selection: Fixed test names-to-IDs mapping when opening the Edit Modal to make sure checkboxes are prepopulated.
  • Safe Persistence: Implemented auto-mapping of test IDs back to full test names when saving, ensuring data integrity in the database.
✨

Expanded Admin Form Configuration

Added inputs for demographic, turnaround, and package priority flags

Added

Integrated additional user interface controls in the Admin Package Modal to configure the exact attributes expected by the patient-facing health checkup cards.

Core UI Controls Configured:
  • Category Selection: Dropdown menu offering catalog tags like Full Body, Diabetes, Heart, Women, Men, Seniors, Infections, Thyroid, and Couples.
  • Ideal For Demographics: Dedicated input field to set descriptive target tags (e.g. "Women 25+ · Hormone & vitality check").
  • Fasting & Popular Status Toggles: Dual slider switches to indicate fasting requirements and whether to overlay the "Popular" badge.
  • Turnaround Time: Custom turnaround hours configuration input mapped directly to report delivery status windows.
  • Days Format Display: Automatically format turnaround hours in days for any duration greater than 24 hours. Implemented custom threshold logic where a fractional day of 0.4 or lower rounds down to the lower day count, and anything higher rounds up to the next full day count (e.g., 80 hours yields 3 days, 82 hours yields 4 days).

Blogs CMS Feature Integration

Created full-featured blogging flow for both patient site and admin panel

Added

Designed and built a complete blogging CMS. Patients can discover articles, search content, and filter by medical category. Admins can manage articles (Create, Read, Update, Delete) and toggle publish status directly from the control panel.

Core Components Configured:
  • Database Integration: Developed `blogService.js` and `blogsData` admin mappings connected to the Supabase `blogs` table.
  • User Pages: Created `/blogs` listing page and a highly-polished, responsive `/blogs/:slug` details page containing cover images, structured paragraphs, metadata badges with icons, social sharing integrations (Facebook, Twitter, LinkedIn), and a "Recommended Reading" related articles section. Redesigned the sidebar CTA screening card with a bright healthcare-themed layout, value proposition checkmarks, and primary red action buttons.
  • Admin Panel: Created `/admin` blogs manager page (`src/admin/pages/Blogs/index.js`), added "Manage Blogs" to the sidebar catalog, and integrated a photo file uploader (`blogsData.uploadCover()`) next to the cover URL field inside the Add/Edit form, enabling real-time preview and bucket upload.
  • Navigation: Added "Blogs" link to the primary header navbar.

Super Administrator Privilege Rules

Restricted administrator creation and management to main admin account

Added

Enforced strict access control constraints across user profile administration: only the main account (medis.com.bd@gmail.com) can promote other accounts to administrator, edit existing admin profiles, block/unblock admins, or delete them.

Core Enforcement Mechanics:
  • Email Authorization: Formulated `isMainAdmin` flags resolving authorization permissions only for the primary email.
  • Action Restrictions: Hidden Edit, Delete, and Status block tools on administrators in the data table when loaded by secondary admin accounts.
  • Form Level Constraints: Disabled/replaced the Role selection input with a read-only text state if edited by secondary admin accounts.
